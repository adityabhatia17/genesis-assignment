**Purpose:** Turn the assignment into an exhaustive, ID'd requirement list; surface the requirements that are implied but not written; resolve every ambiguous phrase once; and state how a reviewer will judge the result. Every other document cites the IDs defined here (`R-*`, `I-*`, `A-*`).

> This file restates the assignment in our own words. When the wording matters, a short quote is used. The PDF remains the authority.

## 1. The assignment in one paragraph

Build **Genesis**, an AI app builder for HighLevel. A user signs up, connects **one HighLevel sub-account (location)** through OAuth, creates a project, and chats with an LLM that **streams** a small web app into a code editor in real time. The generated app must call **real HighLevel APIs** (Contacts, Conversations, Calendars) and a **live preview must render real data** from the user's sandbox. Users can edit files by hand, and **every generation produces a restorable snapshot**. Stack is fixed: **Vue 3 + TypeScript + shadcn-vue** on the front, **Firebase Auth + Firestore + Cloud Functions** on the back, **Claude or OpenAI in streaming mode**. Deliverables: a public GitHub repo, a deployed app (Firebase Hosting + Functions), a README with specific sections, and a Loom of at most five minutes.

## 2. Two products, one distinction

| Product                   | What it is                            | Who runs it        | Trust level                                      |
| ------------------------- | ------------------------------------- | ------------------ | ------------------------------------------------ |
| **Genesis (the builder)** | Vue SPA + Cloud Functions + Firestore | Us                 | Trusted code, holds secrets server-side          |
| **Generated apps**        | HTML/CSS/JS written by the LLM        | The preview iframe | **Untrusted code**; must never hold a credential |

The assignment's "key distinction" is that generated apps are not generic: when the user asks for "a dashboard of my recent contacts and upcoming appointments", the generated code must call the **HighLevel Contacts and Calendars APIs**. How those APIs are exposed to the LLM is left to us ("decide how to best expose them to the LLM") — this is the single most important design question in the assignment and it is deliberately open.

| **Data modeling & versioning** | Tenancy by path, atomic commits, cheap snapshots, restore without loss                                                                                      | Snapshot = random copies; non-atomic writes                                    |

## 9. Scope decision (MoSCoW)

- **Must:** everything in §3.1–3.7 (What to Build, constraints, deliverables) and I-01 … I-12 as needed to ship that product.
- **Won't (this submission):** create/update contact, send message, and free slots (prerequisite “familiarize,” not What to Build); eval harness, Anthropic fast mode, Playwright smoke; multi-location per user, collaborative editing, custom domains, framework-based generated apps, durable resumable generation jobs, marketplace publishing. R-B1 and R-B3 through R-B6 are implemented.
- **R-B2** is not a extra work item: a second prompt uses the same `/generate` path with current files already in context.
